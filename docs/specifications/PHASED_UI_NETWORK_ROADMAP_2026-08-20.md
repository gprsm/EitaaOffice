## قاعدهٔ اجرا

هر فاز جداگانه، با آزمون شکست‌خور پیش از پیاده‌سازی، ثبت رویدادهای امن، اعتبارسنجی و گزارش مستقل بسته می‌شود. شروع فاز بعدی به معنی مخلوط‌کردن دامنهٔ پذیرش فاز جاری نیست.

## فاز ۱ — تنظیم متمرکز پورت

وضعیت: `COMPLETED / AUTOMATED_VERIFIED / NOT_APPLIED_TO_LIVE_CONFIG`

- افزودن بخش Material UI «شبکه و وب» در صفحهٔ تنظیمات؛
- تنظیم پورت داخلی برنامه فقط از همان بخش؛
- همگام‌سازی خودکار Host و Origin داخلی با پورت جدید؛
- حفظ Host و Origin عمومی در حالت Reverse Proxy؛
- ممنوعیت bind مستقیم HTTP روی ۴۴۳؛
- نیاز به تأیید مدیر و اعلام صریح نیاز به اجرای مجدد؛
- عدم تغییر عملیاتی پورت جاری در جریان توسعه و آزمون.

پذیرش: سرویس اتمیک، API سراسری v2، سطح دسترسی فقط‌مدیر برای mutation، رویدادهای audit-required و بخش Material UI تکمیل شدند. Backend برابر `588/588`، assertionهای شماره‌دار UI برابر `70/70`، TypeScript، observability و build موفق‌اند. فایل `bridge.json` واقعی و listener جاری تغییر نکردند.
