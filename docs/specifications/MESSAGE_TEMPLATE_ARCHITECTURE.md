# معماری پیشنهادی تمپلیت پیام

این سند نقطه اتصال نسخه آینده را تعریف می‌کند؛ در GMI 4.2 اجرای خودکار تمپلیت فعال نیست.

## هدف

تمپلیت برای پیام‌های تکرارشونده‌ای است که کاربر پیش از ارسال، چند مقدار محدود مانند نام واحد، تاریخ، مکان یا لینک را تغییر می‌دهد. هیچ تمپلیتی بدون Preview و تأیید صریح ارسال نمی‌شود.

## مدل پیشنهادی

- `template_id`, `name`, `description`, `status`
- متن دارای متغیرهای محدود مانند `{{نام_واحد}}`، `{{تاریخ}}` و `{{مکان}}`
- پیوست اختیاری با مرجع محلی امن، نه مسیر آزاد سیستم
- دامنه مجاز: همه گفتگوها یا Peerهای مشخص
- نسخه، تاریخ اصلاح و کاربر اصلاح‌کننده
- مقادیر پیش‌فرض و Validation هر متغیر
- خروجی Preview نهایی پیش از ارسال

## قواعد ایمنی

- عدم اجرای زمان‌بندی یا ارسال خودکار در نسخه نخست
- عدم Resolve یا افزودن گیرنده پنهانی
- یک ارسال برای یک گفت‌وگوی انتخاب‌شده در هر تأیید
- ثبت نتیجه بدون ذخیره Token یا Session
- فایل‌ها فقط از `runtime/uploads` خوانده شوند
- عبور همه RPCها از Scheduler موجود

## اتصال UI

دکمه «تمپلیت‌های پیام» در `QuickSendBar` نقطه اتصال آینده است. انتخاب تمپلیت باید متن و پیوست را فقط در Draft همان گفتگو قرار دهد؛ کاربر می‌تواند متن نهایی را ویرایش و سپس ارسال کند.
