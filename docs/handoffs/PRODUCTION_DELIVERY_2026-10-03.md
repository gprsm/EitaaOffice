## پذیرش تحویل

V-274 اجرای کامل Backend با یک skip، کنترل‌های UI، بسته‌بندی/wheel، اسناد و
پذیرش نصب واقعی را ثبت می‌کند. پس از درخواست نهایی مالک، V-275 دوباره active
بودن ایتا/Nginx، سلامت سرویس‌های هم‌میزبان و readiness=200 را تأیید کرد.
UI عمومی با TLS معتبر 200 است؛ فایل‌های JS با build پذیرفته‌شده برابرند؛
AppUser status بدون نشست 200 و `/me` بدون نشست 401 است؛ HSTS موجود است.

Config و محیط، حساب‌ها و نشست‌ها حفظ و شش پایگاه داده در V-274 سالم بودند.
هیچ reset، restore، پیام واقعی یا ورود پیام‌رسان در این تحویل انجام نشده است.
هیچ عملیات ضروریِ انتشار یا جایگزینی نسخه برای این استقرار باقی نیست.

## بررسی وضعیت توسط مسئول سرور

پس از اتصال به سرور، این فرمان‌ها فقط وضعیت را می‌خوانند:

```text
sudo publish-site status eitaa-bridge
systemctl is-active eitaa-bridge nginx
docker ps --format '{{.Names}} {{.Status}}'
```

کد هر release مستقل از state مشترک است. پشتیبان سازگارِ پیش از ارتقا، محدود
و فقط روی سرور نگهداری می‌شود؛ اطلاعات ورود داخل این تحویل نیست.
برای انتشار بعدی، مرز F-111 باید لحاظ شود: rollback کد بعد از migration
پایگاه داده تضمین بازیابی سرویس ندارد. بررسی سازگاری و طرح بازیابی داده
مسئولیت انتشار بعدی است؛ restore داده به تأیید همان‌لحظهٔ مالک نیاز دارد.
پذیرش زندهٔ جدید ایتا/بله نیز مأموریت مستقل با مجوز عملیاتی خودش است.
