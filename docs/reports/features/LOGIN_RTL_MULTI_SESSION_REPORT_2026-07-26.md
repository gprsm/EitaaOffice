# گزارش صفحه ورود، RTL و وضعیت چندسشن

تاریخ: ۱۴۰۵/۰۵/۰۴ — ۲۰۲۶/۰۷/۲۶

## نتیجه این مرحله

صفحه ورود بازطراحی و به یک سطح مستقل و ریسپانسیو تبدیل شد. حالت پیش‌فرض رابط دارک است، جهت سراسری سند و تم MUI برابر RTL است و فقط ورودی‌هایی که ذاتاً باید چپ‌به‌راست باشند، مانند شماره تلفن و کد، به‌صورت محلی LTR باقی مانده‌اند.

کاربر اکنون می‌تواند تصویر پس‌زمینه صفحه ورود را هم از دکمه تنظیمات روی همان صفحه و هم از بخش تنظیمات داخلی برنامه انتخاب، تعویض یا حذف کند. تنظیمات شامل محل تمرکز تصویر و شدت لایه تیره خوانایی است.

## پیاده‌سازی انجام‌شده

- سطح ورود جدید با MUI، پنل شیشه‌ای، ساختار مرحله‌ای شماره/کد/رمز دوم و چیدمان سازگار با موبایل، تبلت و دسکتاپ ساخته شد.
- تصویر انتخابی در نسخه Electron به پوشه ثابت `runtime/ui` کپی می‌شود؛ بنابراین وابستگی به مسیر فایل اصلی ندارد.
- فرمت‌های AVIF، JPEG، PNG و WebP تا سقف ۱۵ مگابایت پذیرفته می‌شوند.
- نام فایل و مقادیر تنظیمات پاک‌سازی و محدود می‌شوند و فایل تنظیمات با نام ثابت ذخیره می‌شود.
- در نسخه مرورگریِ توسعه، همان رابط با ذخیره محلی مرورگر کار می‌کند.
- هنگام خواندن و بارگذاری پس‌زمینه، پیش‌نمایش رسانه، آلبوم و آواتارهای مخاطبان از Skeleton استاندارد MUI استفاده می‌شود.
- تنظیم `dir="rtl"` روی سند، `direction: "rtl"` در تم MUI و Emotion cache شامل `prefixer` و `rtlPlugin` فعال است.
- قواعد تکراری `direction` داخل CssBaseline حذف شدند؛ زیرا افزونه RTL آن‌ها را دوباره معکوس می‌کرد و جهت محاسبه‌شده بدنه را LTR می‌ساخت.
- فونت fallback ناموجود حذف شد.
- فرمان‌های Build و Dev برای استفاده از Vite config runner اصلاح شدند.

## وضعیت واقعی چندسشن

نسخه Production در حال حاضر چندسشن نیست:

- `src/eitaa_bridge/application/scheduler.py` صراحتاً یک Scheduler اولویت‌دار تک‌سشن تعریف می‌کند.
- `src/eitaa_bridge/application/api.py` فقط یک `_scheduler` و یک `session_file` فعال دارد.
- پوشه `lab` صرفاً طرح آزمایشگاهی آفلاین است و وارد Runtime محصول نشده است.

برای چندسشن امن، هر حساب باید Process، Scheduler، Session file، database و diagnostics مستقل داشته باشد. Coordinator فقط باید وظایف و گیرندگان را میان Workerهای مستقل تقسیم کند و نباید Session یا اتصال RPC مشترک ایجاد کند.

در این مرحله هیچ قابلیت چندسشن صوری به رابط اضافه نشد. متن صفحه ورود نیز شفاف می‌گوید نسخه فعلی یک حساب فعال را باز می‌کند. فعال‌سازی واقعی چندسشن نیازمند یک مرحله Backend مستقل، تست ایزولاسیون و تأیید جداگانه کاربر است.

## موارد باقی‌مانده

1. باندل JavaScript حدود ۸۲۷ کیلوبایت است و Vite درباره بزرگ‌تر بودن Chunk از ۵۰۰ کیلوبایت هشدار می‌دهد؛ Code splitting هنوز انجام نشده است.
2. معماری قدیمی `ui/src/styles.css` در بخش‌های پس از ورود همچنان چند نسل override و breakpoint دارد. بازطراحی صفحه ورود به‌صورت ایزوله انجام شد و این بدهی فنی را تشدید نمی‌کند، اما پاک‌سازی سراسری رابط هنوز یک مرحله جداگانه است.
3. چندسشن Production هنوز پیاده نشده و نباید پیش از طراحی Worker isolation وارد رابط عملیاتی شود.
4. آزمون‌های Python پس از فراهم شدن محیط دارای `pytest` باید اجرا شوند.

## دروازه مرحله بعد

پیشنهاد می‌شود ادامه کار به دو بخش مستقل تقسیم شود:

1. پاک‌سازی استایل، breakpointها، نوار ناوبری و دارک/RTL کاملِ صفحات پس از ورود.
2. طراحی و اجرای Backend چندسشن با Workerهای کاملاً ایزوله، سپس افزودن مدیریت حساب‌ها و تخصیص ارسال در رابط.

مطابق توافق قبلی، رفع سایر خرابی‌های گسترده و فعال‌سازی چندسشن فقط پس از تأیید کاربر آغاز شود.
