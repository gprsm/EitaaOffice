# عملیات دسته‌ای اعضا و شماره‌ها

MVP 6.1 سه مسیر عملیاتی دارد:

1. ارسال متن، تصویر یا فایل به اعضای گفت‌وگوی فعال؛
2. ورود شماره‌ها از TXT/CSV یا متن چسبانده‌شده، Resolve و ارسال به شماره‌های قابل‌شناسایی؛
3. دعوت برگشت‌پذیر شماره‌های Resolve‌شده به گروه یا کانال انتخاب‌شده.

هر عملیات قبل از اجرا Preview دارد. اجرای واقعی نیازمند تأیید صریح است و به‌صورت Job پایدار Core انجام می‌شود. Pause، Resume و Cancel از API پشتیبانی می‌شوند. تأخیر بین گیرندگان، سقف تست و محدودیت تلاش قابل تنظیم است.

تمام RPCها همچنان از Scheduler واحد عبور می‌کنند؛ عملیات دسته‌ای نمی‌تواند هم‌زمان با RPC دیگر Session را دست‌کاری کند. محدودیت‌های سرور، دسترسی مدیریتی، حریم خصوصی گیرنده و Flood-control ممکن است باعث Skip یا Failure بخشی از گیرندگان شود و باید از گزارش Job بررسی شود.


## معنای دعوت

مسیر دعوت، لینک عمومی تولید یا ارسال نمی‌کند. شماره‌ها ابتدا Resolve می‌شوند و سپس Core برای افزودن یا دعوت حساب شناسایی‌شده به گفت‌وگوی مقصد درخواست مستقیم می‌فرستد. موفقیت به نوع Peer، دسترسی افزودن عضو، وضعیت مدیریتی حساب، تنظیمات حریم خصوصی کاربر و محدودیت‌های سرور ایتا وابسته است. دسترسی به فهرست اعضا نیز براساس پاسخ سرور است؛ مدیر بودن معمولاً دامنه دسترسی را افزایش می‌دهد، اما تنها معیار نیست و بعضی گروه‌ها ممکن است فهرست کامل یا جزئی را برای عضو عادی برگردانند.
